## Deliverable
1. `game/assets/saves/testparty/` = a genuine Pool of Radiance save in the ORIGINAL format (decode/data/SAVES.md: SAVGAM + CHRDATxn.SAV/.ITM/.SPC, 285-byte TChar), generated by `tools/make_test_party.mjs` (node, reuses the build's record code). Six characters, a classic balanced party: fighter, fighter, cleric, magic-user, thief, and one multi-class (e.g. elf fighter/magic-user). Starting level is a **ruling for the owner (PR-n)**: A (recommended) level 3-4, matched to the first areas of Phlan so the opening still plays as designed; B higher (level 7-8) to test later areas and spells. Build A first unless he answers otherwise; make the level a script parameter.
   Stats rolled high but within the game's own creation limits (cite the CreateCharacter checks), HP max, appropriate starting gear for class/level (weapons, armor, shields; memorised spells for the cleric and magic-user), some gold. Healthy, at the Phlan start (the standard post-creation entry point), no quest flags set.
   The shipped `SAVE/CHRDAT*` party (a third-party starter) can be the base if it is valid; say so in README.
   Every field set from the decode; `README.md` lists each character (name, race, class, level, stats, HP, AC, gear, spells) and every field with its source.
2. Loading: `?save=testparty&force=1` copies it into the game's storage before boot (same mechanism as Star Command's engine/saves.js), then the game's own "load saved game" path enters Phlan with this party.
3. Launcher `Play Pool of Radiance (Test Party).cmd` + Desktop shortcut **`<Desktop>\Pool of Radiance - Test Party.lnk`**.
4. Verify headless once the engine can load saves (M2): screenshots of the party roster, one character sheet, and the first Phlan view into `acceptance/testparty/`. Until M2 lands: validate the files by reading them back through the build's SAVES reader and through the original in DOSBox-X (por-dosbox-ref: load the save in the real game and capture the roster; the original accepting it is the strongest check).
